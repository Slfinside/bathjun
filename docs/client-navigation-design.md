# v2.0.0：クライアントのメニューと予約・事前希望（開発版）

この資料はv2.0.0向けに実装した画面構成です。v2.0.0-rcに収録しています。実装した使い方は[開発版ガイド](v2-preview-guide.md)を参照してください。

## 右上メニュー

既存のタイトルとユーザーアイコンの並びにメニューの入口を置き、次の項目をまとめる。

```text
メニュー
├─ ホーム
├─ おふろを予約する
├─ プレゼントボックス
│  ├─ プレゼントボックス
│  └─ 配布履歴
├─ 持ち物
├─ スタンプカード
└─ 設定
   ├─ 既存の各種設定
   └─ ログアウト
```

- ホーム：予約やスケジュールを確認するホーム画面へ戻る。
- おふろを予約する：ホームへ戻り、自分の順番が来ていれば予約入力、まだなら事前希望の入力を開く。入力画面だけ開いても予約・希望を送信しない。入力直前に最新の共有状態を確認する。
- プレゼントボックス：プレゼントボックスと配布履歴を同じ画面内の切り替えで表示する。
- 持ち物：受け取ったアイテムの一覧と説明・使用導線を開く。
- スタンプカード：週間カードの専用画面。ホームにもカードを表示し、専用画面でも前後の週の確認・達成済みの特典受取へ進める。
- 設定：既存のプロフィール・パスキー・通知の種類と何分前か・自動で入らない/様子見にする設定等をまとめ、ログアウトもここへ置く。

将来分の夜でまだ直接予約できない場合は、順番の有無によらず事前希望として扱う。予約済み・開始済み・入浴時間帯終了の場合に、変更可能な予約を開くか状態案内にするかの細部は、既存の操作条件を守って設計する。

## プレゼントボックスと配布履歴

管理者が配布したアイテムは、すぐ持ち物へ加算するのではなく、いったん宛先メンバーのプレゼントボックスへ入れる。受け取る操作で持ち物へ加算する。

- 未受取のプレゼントと、使用可能な持ち物を区別する。
- 受け取りは本人の持ち物だけに反映する。再読み込み・複数端末の同時操作で二重受取が起きないようにする。
- 配布履歴は管理画面だけでなく、メンバーもメニューから見られるようにする。
- 履歴の基本情報は配布日時・対象・アイテム・個数。受取済みかどうかの表示も併せて設計する。
- メンバーに見せる配布履歴は自分宛てのみ。管理画面では全員分を確認できる。表示だけで絞るのではなく、クライアント向けの取得時点でログイン本人宛てに限定する。

週間達成特典は自動抽選してプレゼントボックスへ送る。達成後にホームへアクセスすると、サイトのデザインに合わせたページ内モーダルでお祝いと獲得内容を表示する。ブラウザ標準のalertは使わない。確認済みのお祝いは同じ週に繰り返し表示しない。

## ホームの予約・事前希望の統合

操作するカードは、現在「〇〇さん、選ぶ番です」と表示している枠へまとめる。既存の「事前希望」カードに予約と似た操作が重複して出る構成を改める。

| 本人の状態 | 同じ操作枠に表示する内容 |
| --- | --- |
| まだ順番が来ていない／まだ抽選前 | 事前希望の入力・変更。希望があれば本人の希望内容を確認できるようにする |
| 自分の順番が来た | 「〇〇さん、選ぶ番です」と予約操作。事前希望の入力枠は非表示にする |
| 希望から自動確定した／予約済み | 確定した予約の内容。変更可能な場合は予約変更の操作 |

「みんなの希望」は独立した一覧として残し、共有されている未確定の希望を確認する場所にする。予約操作や本人の希望入力のためのカードとは分ける。

自分の順番で希望が重なり自動確定しなかった場合は、既存の希望を予約入力の初期値として使い、予約する時間を選べるようにする案。本人の希望入力枠が非表示になっても、その希望自体を勝手に削除しない。順番抜かしで予約が希望に戻った場合は、希望の内容と現在の予約可否を共有状態に従って表示する。

iPhoneでは右上メニュー・各画面・入力画面のタップと戻る操作を一貫させる。画面を移動しても、対象の日と選択中のアイテムを意図せず失わないようにする。

## ホームとスタンプカード専用画面

ホームには週間カードの期間と達成状況だけを表示する。前の週やスタンプ獲得履歴は「メニュー → スタンプカード」にまとめる。

メニューボタンは2本線から開いたときの×へアニメーションで変化する。未受取のプレゼントがある間は右上に小さな印を付け、受け取るまで残す。
