# 画面消灯後のサーバー停止：確認と修正（v2.0.0-rc4）

確認日：2026年11月1日。実機から「消灯するとサーバーにも接続できなくなる」との報告を受けて、実装とMicrosoftの電源API資料を確認しました。この修正はv2.0.0-rc4のインストーラ版・ZIP版に含まれます。rc3以前には含まれていません。

## 確認した実装上の問題

- スリープ防止のSystem／Execution要求はWindows管理画面のプロセスが持ち、別プロセスの予約サーバー自身は持っていませんでした。`PowerRequestExecutionRequired`は呼び出したプロセスの実行継続を要求するもので、管理画面側の成功だけで別プロセスの継続を判断できません。
- 手動の画面消灯を自動消灯の状態管理へ反映しておらず、自動消灯が有効な場合は画面維持要求が直後に戻る経路がありました。
- ダッシュボードを開いている場合、手動消灯は実行せず、ダッシュボードを前面に出す処理になっていました。

これらはコード上で確認した問題です。実機で停止した直接の原因がModern Standby、ネットワークの省電力設定、組織のポリシーのどれかは確定していません。

## 修正

予約サーバーのプロセス内から、SystemRequired・ExecutionRequired・継続的なSystemRequiredの要求を取得します。小さなNode-APIモジュールを使い、追加の常駐プロセスやPowerShellは使いません。Windows以外には読み込みません。

管理画面とサーバーの両方の保護が取得できた場合だけ手動・自動消灯を有効にします。取得失敗や配布ファイルの欠損では、予約サーバー自体は動かしますが消灯は無効にします。復帰・電源状態変更時には両プロセスの要求を更新します。

手動・自動は同じ消灯状態を使います。画面維持要求を解除してから、従来どおりWindowsへ実際の画面消灯を要求します。手動消灯は操作完了を待つため約1秒後に実行し、新たなタッチ・マウス・キー操作、または設定した消灯時間帯の終了で点灯へ戻します。ダッシュボードを開いたままでも管理画面・通知領域からの手動消灯に対応します。

Windowsの電源プラン・ロック・組織ポリシーは変更しません。電源ボタン・カバー閉じ・Windowsからの手動スリープは防ぎません。AC電源で運用してください。

## 検証範囲

Nodeの自動テストでは保護要求の成功・不足・取得失敗・解放・再取得を検証します。Windows CIでは配布するものと同じNode.jsで実際の電源要求を取得・更新・解放し、管理画面の手動／自動の干渉・操作による復帰・消灯時間帯終了・保護取得失敗時の無効化を検証します。インストーラ・ZIPの両方に保護モジュールを含め、ファイルハッシュも検証します。

CIはモニターを実際には消しません。物理端末の消灯中にiPhoneから通信できることや、各端末のModern Standby・Wi-Fi・Funnelの継続までは確認できていません。

更新後の実機ではAC電源につなぎ、アプリの消灯ボタンを使い、別端末で家族用リンクを30秒後・2分後・10分後に再読み込みして確認してください。自動消灯も別途確認します。点灯しただけ・パスワード画面が出ただけでは、サーバーが止まったかは判断できません。止まる場合は、Windowsのバージョンと `powercfg /a` の結果が次の切り分けに役立ちます。

## 参照したMicrosoft資料

- [PowerSetRequest](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powersetrequest)：ExecutionRequiredの対象、電池動作時のModern Standby制限、ユーザーによるスリープで要求が終了すること。
- [SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate)：継続的なシステム実行要求。
- [Modern Standby states](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/modern-standby-states)：画面オフから省電力状態へ移行する段階と、実行可能な処理の制限。
