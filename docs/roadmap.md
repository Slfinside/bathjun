# v2.0.0の実装状況

週間カード・完了報告・チケット・配布／受取・クライアントメニューとダッシュボード改修を開発版へ実装しました。[開発版ガイド](v2-preview-guide.md)を参照してください。公開済みv1.3.0にはまだ含まれません。時間帯消灯・点灯も開発版へ実装済みです。公開後の自動更新とタッチスクロールも開発版へ実装済みです。以下のバックアップ・起動一本化等は別の未実装項目です。

| 機能 | 目標 |
| --- | --- |
| 自動バックアップ・復元 | 定期保存と更新前の保存、管理画面からの復元。メンバー・予約・認証・リンクを含むデータを保護し、保存場所と保持数を設定する |
| 起動アプリの一本化・起動方法の記憶 | 起動入口を「ふろきゅ～サーバー」1つに統一。公開／このPC内だけの切り替えはアプリ内で行い、前回の設定を記憶して、次回起動・Windowsサインイン後・更新後も同じモードで起動する。公開の準備・失敗も同じ画面で確認できるようにする |
| 実際の入浴状態 | 「入った／出た」の操作で状態を共有。予約時刻による推定と区別し、押し忘れや予定とのずれも扱う |
| 端末単位のログイン管理 | 端末一覧・最終利用を確認し、紛失端末だけのログイン・通知登録等を解除できるようにする |
| 更新配布元の確認 | 更新ファイルの署名を検証する。署名鍵の安全な保管と公開鍵の配布方法を決め、製品名やチェックサムだけの確認から強化する |

既存データを保持する移行を前提にします。バックアップは認証情報や家族用リンクも含むため、GitHubや配布物には含めません。署名は、Windowsの警告表示に関わるAuthenticode署名と、アプリ内で配布元を検証する署名を区別して設計します。


## 毎週のスタンプカードとチケット（開発版）

日曜〜土曜の7枠を埋める方式に変更する。失敗した枠を補う機能は設けず、1日でも失敗した週は達成不可とし、翌週は新しいカードで始める。土曜夜〜日曜朝の入浴を土曜分に数える週境界を設計する。

達成時はルーレットで「順番抜かし」「+n分」「抽選確率UP（n回）」「順番抜かしガード」のいずれかを受け取る。枚数は管理画面で設定し、初期は各1枚、ガードのみ2枚。時間延長の初期値は30分、抽選確率UPの初期値は3回。チケットは期限なしで持ち越せる。

順番抜かしは開始済みを含む重複する確定予約を事前希望へ戻せるが、ガード付きの予約とは重ねられない。戻された予約で使ったチケットは払い戻さず、時間延長効果も失う。再延長には別のチケットが必要。1つの予約で使用できるチケットは1種類だけとする。従来の「確定済みの予約を動かさない追い越し券」「再抽選券」の案は置き換える。

クライアントに持ち物ボックスを設け、アイテムをタップして説明・所持数・使用条件を確認し、そのまま予約や効果の有効化へ進めるようにする。説明を開く・入力画面に移るだけでは消費しない。管理画面にはメンバー別の持ち物一覧と配布機能を設ける。対象・内容をチェックボックス、個数を入力ボックスで指定し、「配布」で渡す。配布は一度プレゼントボックスへ入り、受取後に持ち物へ加算する。配布履歴はメンバーには自分宛てのみ、管理画面では全員分を表示する。

確定事項・提案・確認中の事項を[スタンプカードとチケットの設計](rewards-design.md)に整理する。開発版に実装し、v2.0.0-rcに収録。


## 起動入口の一本化（v2.0.0で対応）

現行版はデスクトップのローカル起動と、スタートメニューの「固定URLで外部公開」が分かれている。v2.0.0では「ふろきゅ～サーバー」の1アプリから起動・設定・公開を操作する方式にまとめ、公開のたびに別のショートカットを探す必要をなくす。

公開／このPC内のみのモードはアプリ内で選び、選んだ設定を記憶する。すでに起動している場合も同じ画面から切り替えられるようにする。Tailscaleの初回サインインや接続待ち、失敗時の案内は同じ管理画面に集約する。ローカルテストを選んだ場合は外部公開しない。これはv2.0.0の予定で、現行のv1.2.0の起動方法は変更しない。


## v1.3.0へ移した機能

自動で「入らない/様子見」にする個人設定は、v2.0.0予定からv1.3.0へ前倒しする。本人が設定し、初期オフ。新しい夜の初期状態を末尾へ回し、後から通常順へ戻せる。既存の予約・希望、進行中の前夜分は自動で取り消さない。

## 日中・深夜の自動消灯と表示保護（v2.0.0）

開発版へ実装済み。管理画面で時間帯を最大8件指定し、初期は無効、初期の時間帯は08:00〜15:00・02:00〜04:00（日本時間）。終了時刻に自動点灯を要求する。サーバー・通知と自動スリープ防止は継続する。操作があれば1分間点灯し、再び無操作になってから消灯する。設定時間帯とAC接続に基づく動作で、明るさセンサーは使用しない。

小さな位置移動だけではLCDの劣化を防げるとは言えないため、未使用時の実際の消灯を優先し、表示中は配置や内容を大きく切り替える方法も検討する。動くグラデーションは補助候補とし、固定された文字・カードが残るだけの背景アニメーションを十分な対策とは扱わない。

詳しくは[メーカー資料の調査と表示保護の方針](display-protection.md)を参照。これらはv2.0.0の予定で、v1.3.0では実装しない。


## 簡易ダッシュボードと希望の重なり（v2.0.0向けに準備中）

- サーバーダッシュボードは16:9〜3:2の横画面を基準に設計・確認する。簡易・詳細で見出し・人物カード・QRカード・アイコンを共用し、時計は共通の上部に表示する。簡易表示では人物名と時刻を大きく表示し、約0.42秒のアニメーションでカードの位置・大きさ・文字サイズをつなぐ。
- 入浴中は「あと **n** 分｜〜終了時刻」とし、残り分数だけを大きくする。詳細表示では名前の右に収まる場合は横並びにし、収まらない場合のみ別行にする。次の予約は「m分後｜開始〜終了」を同じ文字サイズで横並びに表示する。入浴中の人がいない場合も、次の予約までの分数と予約時間帯を表示する。残り時間はサーバー時刻を基準に切り上げで表示し、開始・終了の境界で表示対象を切り替える。
- QRと「家族用リンク」は横並びにし、簡易表示の右側カード下部に、時間が上から下へ進むスケジュールを表示する。重なる希望は別の列と点線・模様で示す。
- 通常は簡易表示。入浴中の予約がない場合は次の2人と各開始時刻、入浴中の予約がある場合はその人と終了予定・次の人と開始時刻を表示する。時計と家族用QRも表示する。
- 画面をタッチすると詳細表示へ戻る。初期設定では最後のタッチから1分で簡易表示へ戻る。サーバー管理画面の「ダッシュボード」で1〜60分に変更、または詳細表示に固定できる。設定はサーバーPC内に保存し、再起動後も引き継ぐ。画面上には戻るまでの時間の案内を表示しない。人感センサーが不在を示しても、タッチによる詳細表示を優先する。
- 入浴中・終了予定は現在の版では予約時刻による表示。実際の入退浴の自己申告への対応は別項目。
- クライアントとダッシュボードのスケジュールは、共通の時間軸のバーと「重なりあり」で予約・希望の重複を示す。希望は点線、重複区間は文字や模様でも区別する。終了と次の開始が同時刻の場合は重複にしない。
- 消灯終了時刻にはWindowsへ画面の点灯を要求する。PCは起動・ログインを保ち、スリープさせないことが前提。画面の点灯とWindowsのロック解除は別であり、ロックを回避する機能は設けない。自動復帰は実機で確認する。

表示変更はソースで準備中。時間帯消灯・自動点灯はソースへ実装済みで、公開済みv1.3.0にはこれらの変更は含まれない。


## 完了報告と週間達成：今回追加した仕様（v2.0.0の設計段階）

- 入浴完了は自己申告。予約開始から報告でき、予定より早く上がった場合も週間スタンプの成功として数える。受付期限は予定終了からダッシュボードでは1分以内、クライアントでは3分以内とする。
- 未報告の入浴中は「入浴中」の表示と「完了を報告」ボタンを同時に表示する。予定終了を待ってボタンを出す方式にはしない。報告が受理されたら「入浴済」に切り替え、同じ予約の報告ボタンを全端末で消す。
- ダッシュボードの完了報告は簡易表示から直接タップでき、この操作では詳細表示へ移行せず、詳細表示の自動切り替えタイマーにも影響させない。
- 未報告のまま予定終了に達した場合、報告期限までは対象の表示を「入浴中」から「入浴完了」に変え、「完了を報告」ボタンを残す。ダッシュボードの対象切り替えは報告期限を基準にする。
- ダッシュボードでの報告期限は終了から1分、クライアントは3分とする。ダッシュボードの受付終了時点では失敗を確定せず、クライアントの期限まで待つ。期限判定は端末時計ではなくサーバーの受信時刻を基準にする案。
- 報告済みと未報告は内部状態として分ける。端末間で報告を共有し、同じ予約の複数回タップや両端末からの報告で週間スタンプを重複加算しない。
- 日曜〜土曜の週間スタンプカードと特典の達成判定に使う。詳細は[スタンプカードとチケットの設計](rewards-design.md)を参照。

設計上の確認事項：

- ダッシュボードの切り替えは終了1分後、クライアントでは終了3分後まで報告可とする解釈でよいか。
- 前の予約の報告期限と次の予約が重なる場合の配置。次の入浴中の人を隠さず、前の人の報告ボタンを別枠に残す案。
- 未報告の表示が「入浴完了」であっても、報告済みと誤認させないようボタンに「完了を報告」を表示する案。
- 期限内報告を1日の成功とするか、開始の遅れなど別条件も設けるか。

完了報告API・ダッシュボードの報告操作・週間特典の自動抽選とプレゼント送付は開発版に実装済み。


## 右上メニューと予約・事前希望の統合（開発版）

右上メニューに「ホーム」「おふろを予約する」「プレゼントボックス（プレゼントボックス／配布履歴）」「持ち物」「設定（既存の各種設定／ログアウト）」をまとめる。

「おふろを予約する」はホームへ戻り、順番が来ていれば予約、それ以前は事前希望の入力へ進む。ホームの事前希望は、現在「〇〇さん、選ぶ番です」と出る枠へ統合し、自分の順番が来たら事前希望の入力枠を非表示にする。「みんなの希望」は独立した共有一覧として残す。

詳しくは[クライアントのメニューと画面統合](client-navigation-design.md)を参照。メニュー・受取・画面統合は開発版に実装済み。

ホームのスタンプカードは期間・達成状況だけを表示し、獲得履歴や前の週は専用画面で確認する。達成時は特典を自動抽選し、次にホームを表示したときにデザインを合わせたページ内モーダルでお祝いと獲得内容を表示する。
