# v2.0.0：毎週のスタンプカードとチケット（開発版）

これは実装したv2.0.0向け機能の設計資料です。v2.0.0-rcに収録しています。[開発版ガイド](v2-preview-guide.md)に実際の操作と初期設定をまとめています。以前の「任意の7日連続」「失敗を補う券」「予約済みの予定は追い越し券で動かさない」という案を、この資料の仕様に置き換えます。

## 毎週のスタンプカード

- 日曜始まり、土曜終わりの7枠。1人ごとに毎週新しいカードへ交換する。
- 入浴予定を守り、所定の期限内に完了報告できた日にスタンプを押す。予定より早く上がった場合も成功として扱う。
- 7枠すべてが埋まった週を達成とし、ルーレットで予約に有利になるチケットを受け取る。
- 1日でも失敗すれば、その週は達成できない。翌週は新しいカードで始める。
- 失敗を埋める・免除する・凍結する仕組みは設けない。失敗が確定した枠と、まだ期限を迎えていない空欄は区別する。
- 入浴しなかった日は成功にしない。表示の「入らない/様子見」は後から予約できるため、選んだ瞬間の失敗確定とは区別する必要がある。

週の境界：スタンプは画面の「今日」や報告した暦日ではなく、予約が属する入浴日の枠に付ける。例えば土曜15:00〜日曜7:00は土曜分としてその週の最終枠に数え、日曜朝の報告期限まで旧週の受付を続ける。日曜分の予約と旧週の土曜分の報告受付は並行できるようにする。日付切り替え設定や端末時計では付与先を変えない。

## 完了報告

- 予約開始から報告可能。入浴中の表示と報告ボタンを同時に出す。
- ダッシュボードでは予約終了から1分以内、クライアントでは終了から3分以内が報告期限。
- ダッシュボードの報告ボタンは簡易表示から使え、タップしても詳細表示には移行しない。
- 未報告のまま予約が終了したら「入浴完了」へ表示を変え、期限まで報告ボタンを残す。
- 報告を受理したら入浴済みに変え、全端末へ共有する。同じ予約や同じ入浴日に重複してスタンプを押さない。
- ダッシュボードの受付終了だけでは失敗にせず、クライアントの期限まで待つ。
- 受付期限はサーバー時刻を基準に判定する設計。開始時刻の遵守も別にチェックするかは未確定。

## ルーレットでの受け取り

報酬の種類は次の4種類。受け取る枚数は管理画面で設定可能にする。初期値は各1枚、順番抜かしガードのみ2枚。

チケットに有効期限は設けず、翌週以降も持ち越せる。

出現比率の初期値は均等で、管理画面から変更できる。7枠の達成と同時にサーバー側で自動抽選し、プレゼントボックスへ送る。ホームアクセス時にページ内のデザインを合わせたお祝いモーダルで結果を表示する。確認済みの週のお祝いは繰り返さず、特典は受け取るまでボックスへ残す。

結果を確定してから演出を再生し、再読み込み・端末の変更・同時操作で引き直しや二重受け取りが起きないようにする。

## 持ち物ボックス

メンバー本人のクライアント画面に持ち物ボックスを設ける。アイテムのアイコン・名前・所持数を並べ、タップすると説明と使用操作を開く。iPhoneで扱いやすいタップ領域とし、既存の画面とカード・色・文字をそろえる。

説明には効果・所持数・使用条件・消費するタイミングを記載し、「使う」から対象の操作へ直接進める。予約に使うアイテムでは、対象の日とアイテムの選択を引き継いで予約・事前希望の入力画面へ移動する。アイテムを使うために通常の予約順を飛ばせるのは順番抜かしチケットだけとする。

| アイテム | 説明から進む操作 |
| --- | --- |
| 順番抜かし | チケットを選択済みの予約画面へ。重なる予約が事前希望へ戻ることを確認して確定 |
| +n分 | 延長チケットを選択済みの予約画面へ。順番待ちの場合は事前希望へ指定でき、確定時に消費 |
| 抽選確率UP | 次回以降の抽選に効果を有効化する使用操作へ。初期3日間・1番の確率が3倍になることを表示 |
| 順番抜かしガード | ガードを選択済みの予約・事前希望画面へ。事前希望への指定では消費せず、確定時に消費 |

説明を開く・予約画面へ進む・入力を取り消すだけでは消費しない。予約向けアイテムは確定と消費を一緒に処理する設計。抽選確率UPは有効化する操作で使用済みにし、以後の適用残日数を表示する。失敗した操作や連打・別端末の同時操作で枚数が余分に減らないようにする。

1つの予約に使えるチケットは1種類だけ。別のチケットを選び直した場合は、同じ予約への併用にならないよう現在の選択を置き換える。所持数だけでなく抽選確率UPの発動中・残日数も確認できるようにする。

ボックスと使用導線は追加する仕様として確定。配置の細部や消費時点が未確定の券については設計を続ける。v2.0.0-rcに収録。

## 管理画面の持ち物一覧とアイテム配布

管理者はメンバーごとのチケット所持数と、抽選確率UPの発動中の残日数を確認できるようにする。週間報酬とは別に、管理画面からアイテムを直接配布できる。

配布画面の入力は次の形とする。

- 対象：メンバーをチェックボックスで選ぶ。複数選択可能。
- 内容：アイテムの種類をチェックボックスで選ぶ。複数選択可能。
- 個数：数値の入力ボックスで指定する。
- 操作：「配布」ボタンを押して配布する。

複数選択した場合は、選んだ各メンバーへ、選んだ各アイテムを指定個数ずつ配る解釈で設計する。個数はチケットの枚数であり、時間延長の分数や抽選確率UPの適用回数の設定とは分ける。配布したアイテムは宛先メンバーのプレゼントボックスへ入れ、本人が受け取ってから持ち物へ反映する。対象・内容の未選択、正の整数でない個数は配布できない。

配布履歴はメンバーからも見られるようにする。右上メニューの「プレゼントボックス」内に、プレゼントボックスと配布履歴をまとめる。メンバーには自分宛てだけを表示し、管理画面では全員分を確認できる。詳しくは[クライアントのメニューと画面統合](client-navigation-design.md)を参照。管理画面の一覧・配布・受取操作も含め、開発版に実装し、v2.0.0-rcに収録。

## 順番抜かしチケット

- 通常の予約順を待たずに予約できる。既に確定した予約との重なりも、このチケットでは処理できる。
- 重なった既存の予約は事前希望へ戻す。開始済みかどうかで対象を制限しない。複数人と重なる場合は、対象となる全員を戻す。
- 戻された予約で使ったチケットは、使用済みのままにし、払い戻さない。
- チケットを使った予約には、その旨を表示する。
- この予約も、後から別の順番抜かしチケットを使った人の影響を受ける。チケットを使っただけでは保護されない。
- ガード付きの予約と重なる場合は予約を確定できない。一部の予約だけを希望に戻して処理途中で失敗することがないよう、まとめて判定する。
- 開始・終了時刻が接するだけなら重複としない。

開始済みの予約も対象にできる。入浴時間帯・所要時間の上限・刻み幅は引き続き守る案。

押し出された人の扱いは要設計：元の開始・終了・備考を希望へ引き継ぎ、本人へ通知する。希望へ戻すことで元の予約順から取り残されないようにする。使用済みチケットは払い戻さず、時間延長の効果も希望へ引き継がない。再度上限を延ばすには別の時間延長チケットが必要。元の所要時間が通常の上限を超える希望は、時間を短くするか、新しい延長チケットを指定するまで再確定できない。希望の長さを勝手に短縮しない。

## +n分チケット

- その予約について、通常の1回の上限をn分増やす。
- nは管理画面で設定し、初期値は30分。
- 予約の刻み幅が15分なら、延長も15分単位で設定できるようにする。他の刻み幅の場合も同様。
- 順番抜かしの効果はない。単独使用では他人の確定予約と重ねられない。

チケットを使っても入浴時間帯をはみ出せない、同じ予約に何枚も重ねて上限を増やせない、予約が確定した時に消費する、という案。押し出された場合は消費済みのまま効果も失う。本人の予約変更では同じ予約の延長分を維持し、キャンセル後は払い戻さない。設定変更により30分が刻み幅と合わなくなる場合の扱いも決める。

## 抽選確率UP（n日間）チケット

- 使用からn日間、本人が予約順1番になる確率を未使用の人の3倍にする。
- 未使用者の重みを1、効果中の人を3とし、本人が1番になる確率は `本人の重み / 参加者全員の重みの合計`。
- 5人のうち1人が効果中なら、効果中は3/7、ほかの各人は1/7。
- 4人のうち3人が効果中なら、効果中の各人は3/10、ほかの1人は1/10。
- 複数人が使用しても個々の重みは3。全員が使用している場合は同確率になる。

初期のnは3日間（使用から72時間）。管理画面で変更する。1番だけ重み付きで選び、残りの順番は通常の無作為抽選にする。抽選しない日も時間は進む。固定順では効果を使わないが、有効期限は停止しない。

追加使用は倍率を増やさず、現在の有効期限から日数を加算する。使用済みの効果と期限は再起動後も保持する。旧RCの有効化済みの残回数は更新時に同じ日数へ一度だけ移行する。

## 順番抜かしガード

- 予約時に使用する。事前希望を出す時点でも使用するか指定できる。
- 希望を出した段階では消費せず、予約が確定した時に消費する。
- 確定した予約にはガード付きであることをスケジュール上で明示する。
- ガード付き予約に重なる順番抜かし予約は確定できない。
- 順番抜かしを実際に受けなくても、確定時に消費したガードは使用済みとなる。
- 初期の受け取り枚数は2枚。

複数日の希望に同じ残り1枚を指定した場合は、最初に確定した予約で消費し、他の日の希望を勝手にガードなしで確定しない案。希望だけではチケットを二重に確保できないことを表示する。予約変更では同じ予約のガードを維持し、キャンセル後は払い戻さない。

## 予約時のチケットの併用

- 1つの予約に使用できるチケットは1種類だけ。順番抜かし・時間延長・ガードを同じ予約に併用しない。
- このため、順番抜かし予約を同時にガード付きにしたり、順番抜かしと時間延長を組み合わせたりすることはできない。
- 抽選確率UPは抽選に対する効果であり、予約時に選ぶ上記3種類とは作用する場面が異なる。

## 今回確定した補足

- 順番抜かしは開始済みの予約も対象にできる。
- 事前希望へ戻された予約の使用済みチケットは払い戻さない。
- チケットは期限なしで持ち越せる。
- 押し出された予約の時間延長効果は失われ、再延長には別のチケットが必要。
- 1つの予約で使えるチケットは1種類だけ。
- 抽選確率UPは初期3日間、管理画面で変更できる。

初期の出現比率・予約変更とキャンセル時の扱い・自動送付時刻は[開発版ガイド](v2-preview-guide.md)に記載。週途中に参加した場合もその週の7枠すべてが必要で、欠けた日を救済しない。

## チケットの予約時間制限

延長・順番抜かしは初期設定で開始まで120分以下の予約に使用できない。延長は予約全体が19:00〜23:00と重なる場合も禁止する。半開区間で判定し、19:00終了・23:00開始は許可する。管理画面で分数（0で無効）と延長の禁止時間帯（オン・オフ、日跨ぎ可）を変更できる。

希望提出時と自動確定時、予約の作成・時刻変更時にサーバーで再検証する。拒否時は消費も押し出しも行わない。時刻を変えない既存予約の備考編集は許可する。
