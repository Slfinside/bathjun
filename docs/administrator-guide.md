# 管理者向け：導入・設定・運用

この文書は再公開したv2.0.0-rcの手順です。[日付・予約の区切り](calendar-days.md)と曜日ごとの自動予約にも対応しています。

サーバーを管理する人向けの手順です。予約する人は[利用者向けガイド](user-guide.md)、ソースから動かす場合は[開発者向けガイド](development.md)を参照してください。

配布物は[RC版のGitHub Release](https://github.com/Slfinside/bathjun/releases/tag/v2.0.0-rc)から取得します。インストーラーは `Bathjun-Setup-x64.exe`、このPC内で試す版は `Bathjun-Portable-x64.zip` です。「Source code」は開発用で、起動環境は同梱していません。

## 接続の仕組み

Windows PCで予約サーバーを動かし、Tailscale Funnelを通して固定のHTTPSリンクを発行します。家族はSafariなどのブラウザーからそのリンクを開きます。同じWi-Fi内でも、外出先のモバイル回線でも、共有するリンクは同じです。

```text
家族のiPhone・ほかの端末
    ↓ 家族用のHTTPSリンク
Tailscale Funnel
    ↓
管理者のWindows PC上のふろきゅ～
    ↓
そのPC内に保存する予約データ
```

- iPhone側にTailscaleをインストールする必要はありません。
- ルーターのポート開放や、独自ドメインの購入は不要です。
- アプリ用の有料クラウドサーバーは使いません。Tailscale側で利用可能な無料プラン・Funnelの条件に従います。
- 公開用のPCでは、Tailscaleのインストール・サインイン・HTTPS/Funnelの許可が必要です。Tailscaleの初回導入にはWindowsの管理者権限が必要です。
- PCの電源・インターネット接続・ふろきゅ～の公開起動を維持してください。PCが停止・スリープしている間は、アクセスと通知送信が止まります。

## どの版・起動方法を使うか

| 版・起動方法 | 接続できる端末 | 用途 |
| --- | --- | --- |
| ZIP版の「はじめる.cmd」 | 起動したPCのみ | 管理者権限を使わないローカルテスト |
| インストール版のデスクトップ「ふろきゅ～」 | 起動したPCのみ | ローカル動作確認 |
| インストール版のスタートメニュー「固定URLで外部公開」 | 家族のiPhone・別PCなど | 固定HTTPSリンクによる運用 |

現在のZIP版は `127.0.0.1` だけで待ち受けます。同じWi-FiのiPhoneでも接続できません。`localhost` や `127.0.0.1` は、そのリンクを開いている端末自身を指すため、PCのローカルURLをiPhoneに送っても接続できません。

学校などの管理対象PCで権限・実行許可・ネットワーク許可がない場合は、ローカルテストまでにしてください。端末や組織の制限を回避する設定は行いません。

## 1. 公開用Windows PCを準備する

Windows 10/11の64bit版と、.NET Framework 4.7.2以降を使います。更新済みのWindowsでは通常、既存の.NET Frameworkを利用できます。

1. 配布された `Bathjun-Setup-x64.exe` を実行します。
2. **「無料固定URL用のTailscale」** を選びます。すでに導入済みなら既存のTailscaleを利用できます。本体だけの導入は管理者権限なしですが、Tailscaleの初回導入にはWindows管理者の許可が必要です。
3. 最初の起動で、家族共通の合い言葉を設定します。合い言葉は8〜128文字です。
4. サーバー操作画面の **「設定」** で、「追加する名前」にメンバー名を入力し、**「メンバーを追加」** を押します。人数分繰り返したら **「設定を保存」** を押してください。追加した人は「利用する」がオンになります。初期状態にはメンバー名は入っていません。
5. 必要に応じて予約・スタンプの区切り（初期7:00）・抽選／固定順・予約時間の長さを設定します。名前・利用状態は保存後すぐ、時間と順番の設定は翌日分から反映します。
6. ローカルモードが動いていたら **「サーバーを停止して終了」** で停止します。

## 2. 固定URLで公開する

1. スタートメニューのふろきゅ～のフォルダーから、**「固定URLで外部公開」** を開きます。
2. 初回は開いたページでTailscaleのアカウントにサインインします。HTTPSとFunnelの利用を求められたら、内容を確認して許可します。
3. 接続確認が完了し、操作画面が稼働状態になって家族用リンクが表示されるまで待ちます。起動途中やエラー中のローカルURLは共有しません。
4. 操作画面の **「リンクをコピー」** でコピーし、家族だけに渡します。合い言葉も家族に伝えます。

リンクの形式は次のようになります。以下は形式だけの説明で、実際には接続できません。

```text
https://<PCのDNS名>.<tailnetのDNS名>.ts.net:8443/family/<長いランダムな文字列>/
```

**`:8443` と `/family/…/` を含めて、表示されたリンク全体をそのまま共有してください。** この実装のFunnel公開ポートは8443です。認証後のブラウザーのアドレス欄は短いルートURLになる場合があるため、操作画面のコピー機能、または予約画面の「家族用リンクをコピー」を使います。

PCのTailscale登録・DNS名・アプリのデータを維持すれば、通常の再起動で同じリンクを使えます。TailscaleのPC削除・DNS名変更・ふろきゅ～の全データリセットではリンクが変わるため、新しいリンクを共有し直します。

## 3. 家族のiPhoneで初回設定する

1. 管理者から受け取った長い家族用リンクを **Safari** で開きます。
2. 家族共通の合い言葉を入力します。認証前には、メンバー名や予約内容は表示されません。
3. 自分の名前を選び、復旧用の個別パスワードを設定します。4〜128文字で、絵文字と色も選びます。他の人の名前には設定しません。
4. Safariの共有メニューから **「ホーム画面に追加」** を選びます。「Webアプリとして開く」が表示されたら有効にして追加します。
5. 追加したふろきゅ～を開き、必要ならもう一度ログインします。
6. **「パスキーを登録」** から、Face ID・Touch ID・端末のパスコードなどでパスキーを登録します。
7. ホーム画面から開いたアプリで **「通知を受け取る」** を押し、通知を許可します。予約順が来たときに加え、自分の設定した分数前にも通知します（初期10分前）。iPhoneのプッシュ通知にはiOS 16.4以降が必要です。

パスキーや通知を設定した後は、通常の設定案内が隠れます。変更するときは折りたたみの **「ログイン・通知の設定」** を開きます。

## 4. 二回目以降と、ほかの端末

- ホーム画面のふろきゅ～を開きます。ログインが残っていれば、そのまま使えます。
- ログインが切れていたら **「パスキーでログイン」** を使います。登録済みのパスキーで本人を確認できれば、家族共通・個別の両パスワード入力を省略できます。
- 新しい端末では、同じ家族用リンクを開きます。同期されたパスキーが使えればパスキーでログインでき、使えなければ合い言葉と自分の個別パスワードで入って、その端末でパスキー・通知を設定します。通知の許可・登録は端末ごとです。
- 別のPCやAndroidなども、同じ家族用HTTPSリンクをブラウザーで開きます。パスキー・通知の利用可否は、その端末とブラウザーの対応状況に従います。

## 5. サーバーを棚などで稼働させる

1. 公開用PCをAC電源につなぎます。
2. **「固定URLで外部公開」** で起動して、接続完了とリンクを確認します。
3. 管理画面の **「画面だけ消す（サーバーは継続）」** を押します。
4. 初回はPCの画面が消えた後、iPhoneでリンクを開けるか確認します。Wi-Fiを切ってモバイル回線でも試すと、外出先からの接続確認になります。

操作画面の×は通知領域にしまう操作です。終了するときは **「サーバーを停止して終了」** を使います。電源ボタン・カバー閉じなどの手動スリープや、OSの再起動・電源断は防ぎません。

現在のサインイン時自動起動は **ローカルモード** です。Windowsを再起動した後、iPhoneから使うには、ローカルサーバーを停止して **「固定URLで外部公開」** を起動してください。ログアウト・再起動後に無人で公開モードへ戻る構成ではありません。

## 接続できない・通知が来ないとき

| 状況 | 確認すること |
| --- | --- |
| PCでは開けるが、iPhoneで開けない | ZIP版やデスクトップのローカル起動になっていないか。「固定URLで外部公開」で発行したリンクか |
| 家族用リンクが表示されない | Tailscaleの導入・サインイン・HTTPS/Funnel許可・PCのネット接続が完了しているか |
| 404になる | `:8443/family/…/` まで含む正しいリンクか。全リセット後など、古いリンクを使っていないか |
| PCの再起動後に使えなくなった | ローカルモードではなく、公開モードを改めて起動したか |
| パスキーを使えない | 初回登録と同じ固定HTTPS先か。パスキーが端末にあるか。必要なら個別パスワードで復旧する |
| 通知が来ない | iOS 16.4以降か。ホーム画面のアプリから通知を許可したか。端末の通知設定とサーバーの稼働を確認する |
| 希望が予約になっていて順番通知が来ない | 設定した優先ルールを満たす事前希望は、順番到来時に自動確定する。次に手動操作が必要な人が順番通知の対象。自動確定した本人も予約開始前の通知は受け取る |

## 管理とデータの取り扱い

- 通常版のデータは `%LOCALAPPDATA%\BathjunData`、ZIPテスト版は `%LOCALAPPDATA%\BathjunTestData` に保存します。
- パスワードを忘れた場合は、管理画面の **「パスワード・リセット」** で設定状態・入力内容の照合・変更を行います。現在のパスワードそのものは復元表示できません。
- 個別パスワードの変更はその人、共通の合い言葉の変更は全員のログイン・パスキー・通知登録を解除します。
- 全データリセットはメンバー・予約・設定・認証情報などを消し、家族用リンクも更新します。確認のため「リセット」と入力してから実行します。
- **実際の家族用リンク、合い言葉、個別パスワード、家族の名前、データベース、秘密鍵、バックアップはGitHubに載せません。** この文書のURLは説明用の形式だけです。

LANのHTTP接続では通信が暗号化されないため、通常運用には固定HTTPSリンクを使ってください。3000番ポートをルーターから直接公開する必要はありません。[セキュリティ確認結果](security-review.md)に、修正済みの問題と残る改善候補をまとめています。

この手順は現在の実装に合わせたものです。クラウド内では、実際のWindowsでのTailscaleサインイン・公開URLの発行、物理iPhoneでのFace ID・プッシュ通知、画面消灯後の接続維持は未検証です。運用するPCとiPhoneで、初回に上記の接続確認を行ってください。

### 予約開始前の通知

同じ通知許可で利用できます。自分の確定済み予約の設定した分数前に送り（初期10分前）、予約変更では新しい時刻へ合わせます。キャンセル・様子見・通知解除・ログアウト時は取り消します。予約や通知登録が設定した通知時刻を過ぎていれば、開始前に限り即時通知します。サーバー再起動後も予定を復元しますが、予約開始後に遅れて送ることはありません。PCの停止中は送れず、端末のOS・回線により遅延する場合があります。


## 常時表示ダッシュボード

「稼働状況」タブの **「ダッシュボードを開く」** から開きます。全画面になり、右上の「戻る」をタップするか Esc / F11 で閉じます。閉じてもサーバーは継続します。

- 次にお風呂に入る人と開始時刻、その下に現在の人と終了時刻。
- 今の夜全体の予約・未確定の希望。時刻順に表示し、表示しきれない場合は12秒ごとにページを切り替えます。
- 詳細表示は左に現在・次の人とQR、右に縦長のスケジュール。簡易・詳細ともメンバー一覧は表示しません。
- 日本時間の時計、サーバー接続状態、最終更新時刻。
- 外部公開が稼働確認できたときだけ、長い家族用リンクのQR。ローカルモードでは出しません。

**入浴中・入浴済は予約時刻から判定します。実際の入退室を検知する機能ではありません。** 次の人も未確定の希望ではなく、確定した予約から選びます。予約の区切りと実際の入浴中・報告待ちを基準に表示する日を選びます。区切りをまたいで入浴中の場合も、その予約の所属日を表示します。

表示中だけ5秒間隔でローカル管理用通信から読み込みます。表示だけで抽選・予約を変更することはありません。20秒以上更新できなければ警告し、現在・次の人とQRの表示を止めます。時計は最後のサーバー時刻を基準に進みます。

### 消灯と焼き付き対策

AC電源につないで使ってください。ダッシュボード表示中はWindowsへ自動スリープ防止に加え、自動消灯を抑える要求を出します。閉じると消灯抑止を解除し、通常のサーバー運用へ戻します。画面内は暗い背景と明るさを抑えた配色にし、30秒ごとに表示位置をずらします。詳細表示のスケジュールは右側に固定します。QRの周囲も一緒に移動します。焼き付きを完全に防ぐ保証はありません。

手動の電源ボタン、カバー閉じ、Windowsのロック、スクリーンセーバーや組織のポリシーを無効化する機能ではありません。抑止要求に失敗した場合はダッシュボード内に表示します。Windows実機で最初に動作を確認してください。

手動・自動消灯は、管理画面と予約サーバーの両方でスリープ防止を取得できた場合だけ利用できます。ダッシュボードを開いている場合も通知領域の「画面だけ消す」から消灯できます。消灯から戻すときは画面タッチ・マウス・キーボードを使ってください。電源ボタンはスリープを発生させる場合があります。パスワード画面が出るだけではスリープしたかは断定できません。消灯中に別端末から予約画面を再読み込みできるかで、サーバーが応答していることを確認できます。

### 人感センサーによる表示切り替え（任意）

「稼働状況」の **「人感センサーで表示の明るさを調整（対応端末のみ）」** は初期状態でオフです。有効にしてからダッシュボードを開くと、Windows HumanPresenceSensor が利用可能な端末で次のように切り替わります。変更は次にダッシュボードを開いたときに反映します。

| 検知状態 | 表示 |
| --- | --- |
| 在席 | 時計・スケジュール・一覧・QRを、文字を明るくして表示 |
| 不在 | 遠くから見えるように、次の人と開始時刻を大きく、明るさを抑えて表示 |
| 非対応・権限なし・判定不能・エラー | 通常の詳しい表示を維持 |

**Windows Helloの顔認証カメラがあるだけでは使えません。** 対応するWindows 11のAPIと人感センサー、ドライバー、Windows側の利用許可が必要です。在席の検知であり、誰が見ているか・視線・入浴の有無は識別しません。Windowsのセンサー読み取りのみを使い、独自にカメラを起動・録画・保存しません。不在でも画面は消灯しません。変更するのは画面内の配色とレイアウトで、OSのディスプレイ輝度ではありません。

設定はPCのデータフォルダーの `dashboard-presence.txt` に保存します。設定がオフならセンサーへアクセスしません。対応センサーの実機検証は未実施です。

## 更新とバックアップ

1. 管理画面で **「サーバーを停止して終了」** を押します。×は通知領域へしまう操作なので、更新前の停止には使いません。
2. 通常版は `%LOCALAPPDATA%\BathjunData`、ZIP版は `%LOCALAPPDATA%\BathjunTestData` をフォルダーごと安全な場所へコピーします。リンク・秘密鍵・認証データを含むため公開しないでください。
3. 通常版は新しいインストーラーを上書き実行します。ZIP版は新しいフォルダーへすべて展開し、「はじめる.cmd」を実行します。同じWindowsユーザーならテストデータを引き継ぎます。
4. 外部公開で使う場合は、更新後も「固定URLで外部公開」で起動してください。デスクトップやサインイン時自動起動はローカルモードです。

更新・アンインストールで既存データを自動削除しません。初期メンバーは空で、配布ソース・配布ファイルには実際の予約やメンバー名を含めません。


### 管理画面から更新する

公開配布後は「稼働状況」の **「最新版を確認」** から、版の確認・ダウンロード・検証・更新・再起動へ進めます。確認画面で更新を選ぶと、その端末のインストール版／ZIP版に合うファイルを取得します。ダウンロード中は予約サーバーを動かしたままにし、適用直前だけ停止します。取得中の同じボタンで中止できます。

**現在のリポジトリは非公開のため、自動取得は利用できません。** アプリにGitHubのパスワードやトークンを設定する機能はありません。公開後に使える仕組みとして用意しています。取得できない場合は従来どおりブラウザーでリリースページを開きます。非公開の間は、[公式Release](https://github.com/Slfinside/bathjun/releases)へ権限のあるアカウントでログインしてダウンロードしてください。

- インストール版は `Bathjun-Setup-x64.exe` と同名の `.sha256` を取得し、「インストーラーを選んで更新」から実行します。同じ場所にチェックサムを置くと照合します。
- ZIP版を手動更新する場合は新しいフォルダーへ展開し、サーバーを停止して「はじめる.cmd」を実行します。同じWindowsユーザーならテストデータを引き継ぎます。

自動取得ではSHA-256、配布先、バージョンを必ず確認します。ZIPは内部ファイルのマニフェストも検証し、データ領域以外のアプリを入れ替えます。入れ替えに失敗した場合は元のアプリへ戻す処理を行います。インストール版の公開／ローカル起動モードも引き継ぎます。

正式版は正式版の更新のみ、RC版はRCと正式版の両方を対象にします。同じ版や古い版は受け付けません。最初にこの機能のある版へ移るときは手動更新が必要です。更新中はアクセスと通知が一時停止します。実機での再起動・公開モード復帰は未検証です。

更新補助用の一時ファイルは `%TEMP%\Bathjun-Update-*` に作ります。ZIPの復元にも失敗した場合は、元のファイルを保持した `.bathjun-update-*` フォルダーがアプリの場所に残ります。サーバーを停止してから確認し、必要に応じて公式の配布物から手動で復旧してください。

### タッチでのスクロール

管理画面は、余白や設定項目の上を上下にスワイプしてスクロールできます。メンバー表や対象の一覧に指を置いた場合は、まず一覧の中をスクロールします。ボタンはタップ、入力欄はタップして編集します。スクロールバーやマウスホイールも引き続き使えます。

### 予約画面と共通のデザイン（1.1.2以降）

ダッシュボードは予約画面と同じ Noto Sans JP の通常・太字、ロゴ、緑とオレンジ、丸いカードを使います。メンバーのアイコンも予約画面の設定を表示します。常時表示の明るさを抑えるため、ダッシュボードは暗色の同系色です。16:9〜3:2の横画面を想定し、スケジュールは右側を上から下へ進みます。

フォントはアプリに含まれ、Windowsへのフォントのインストールや、外部フォントサービスへのアクセスは不要です。ブラウザーは初回だけ取得し、同じ端末で再利用します。SIL Open Font License と出典は `app/public/fonts/` に同梱しています。


## 日付と朝の並行利用

「今日」と抽選の対象日は、日本時間の0:00で切り替えます。入浴開始・終了の設定は廃止し、「設定」の **「予約・スタンプの区切り」** を初期7:00としています。保存した翌日分から適用します。

午前3:00の「今日」は当日7:00〜翌7:00未満に開始する予約です。朝6:30〜7:30の予約は前日分として扱い、終了時刻で所属日を変えません。今朝の予約は「昨日」から確認し、当日分の抽選・予約は「今日」で行います。ダッシュボードは入浴中や報告待ちの前日予約も表示します。

先行抽選はできません。抽選時間制限を有効にした場合はその設定にも従います。明日・明後日には事前希望を出せます。[移行と具体例](calendar-days.md)も参照してください。

## 通知の種類と分数（1.2.0以降）

本人が予約画面の「ログイン・通知の設定」で変更します。種類・分数はメンバーごとに保存して端末間で共有します。本人以外の設定を変更する公開APIはありません。

- 事前希望が予約として自動確定した。
- 自分の順番で、重複・時刻条件などにより希望を確定できなかった。
- 予約する順番が回ってきた。
- 入浴開始の指定した分数前になった。1〜180分前、初期10分前。

4種類とも個別に有効・無効を切り替えられます。希望の結果は同じ申請・結果について繰り返し通知せず、未確定だった希望が後から確定すれば確定通知を別に送ります。変更・取り消しで不要になった未送信の結果通知は抑止します。入浴前通知の分数を変更すると未送信の予定を組み直し、同じ予約ですでに送信済みの通知を繰り返しません。

初期値はすべて有効ですが、端末の通知登録・OSの許可も必要です。解除・ログアウト・利用停止などで送信先が失効した場合は送りません。サーバー停止中は送れず、OSや通信による遅延はあり得ます。


## 希望の自動確定と予約順の優先（1.3.0以降）

管理画面の「設定」に **「下位の人の希望と重なっても自動確定する」** を追加しました。初期はオンです。

- オン：自分の順番で、下位の人の未確定の希望だけが重なっている場合も自動確定します。
- オフ：従来どおり、ほかの人の希望との重複がある場合も保留します。
- どちらでも、確定済みの予約との実際の重複は認めません。終了と次の開始が同じ時刻なら重複にはしません。

上下の判定は、様子見による移動を反映した実際の予約順を使います。利用停止中の人の希望は自動確定を妨げません。順番に入っていない人など、下位と判定できない希望との重複は保留します。

この設定は **保存後すぐに当日分にも反映し、保留中の希望を再判定** します。確定済みの予約を設定変更で取り消したり、重複する予約を作ったりはしません。

## 自動で「入らない/様子見」にする設定（1.3.0）

本人が予約画面の「ログイン・通知の設定 → 毎日の予約設定」で選びます。初期はオフで、次に順番を決める夜から適用します。すでに順番が確定した夜は変更せず、抽選前ならその夜から使えます。抽選・固定順の確定時に初期状態を適用し、サーバー再起動や再読み込みで手動の復帰を上書きしません。

自動の人同士は抽選・固定順の元の順番を保って末尾へ並び、後から手動で末尾へ移動した人はその後に並びます。朝まで続いている前夜分、既存予約、事前希望は自動で取り消しません。データの全リセットではこの個人設定も初期化します。

## LCDの残像と画面保護について

小さな位置移動だけでパネルの劣化を防げるとは限りません。LCDでは暗い配色と実際のバックライト輝度も別です。[メーカー資料の調査とv2.0.0の対策方針](display-protection.md)を参照してください。時間帯による自動消灯などはv2.0.0向けの予定で、1.3.0には含めません。

## 画面の自動消灯・自動点灯（開発版）

「ダッシュボード」タブで「時間帯で自動消灯・点灯する」をオンにして「表示設定を保存」を押します。初期はオフで、08:00〜15:00、02:00〜04:00（日本時間）が入力されています。1〜8件の時間帯を編集でき、日跨ぎにも対応します。

画面だけを消し、終了時刻に自動点灯を要求します。サーバー・通知・自動スリープ防止は継続します。タッチなどの操作中と、その後1分間は点灯します。ダッシュボードを閉じていても有効です。AC接続で使用してください。

画面の点灯とWindowsのロック解除は別です。ロックや電源ボタン・カバー閉じによるスリープの設定は変更しません。実機の電源制御は未確認のため、最初に自動点灯することを確認してください。詳しくは[開発版ガイド](v2-preview-guide.md#自動消灯自動点灯)を参照してください。

## 日本語表示名の変更

日本語名は「ふろきゅ～」です。bathjunのリポジトリ名・配布ファイル名・データ保存先・共有URL・パスキーのRP IDは継続し、版番号も同じ系列で進みます。名前の変更のためにデータをリセットする必要はありません。

旧名の管理画面では新しい製品名のインストーラーを認識できない場合があるため、最初の移行は新しいインストーラーを同じ場所へ上書きしてください。移行後の更新処理は旧名・新名の両方を検証できます。

## アイテムと完了報告の設定（v2.0.0-rc）

「アイテム・特典」タブの上部で設定し、下の「特典設定を保存」を押します。

- アイテム機能：初期有効。無効中は使用・受取・配布と確率UP適用を止め、クライアントの予約関連から表示を隠します。プレゼントと持ち物は確認用に残し、データは削除しません。確定済み予約の効果は保持します。無効中に達成した週の報酬は、再有効化後の本人のアクセス時に発行します。
- 連続して入らない日数：1〜30日、初期2日。「入らない/様子見」を保留し、設定日数続けて入浴時間帯が終了したら遡って失敗にします。それより先に翌日の入浴完了を報告すれば保留も成功になり、前の週の報酬も後から届きます。既に確定した結果は設定変更で変わりません。自動の様子見にも適用します。
- 完了報告：クライアント／ダッシュボードそれぞれ1〜180分で設定。初期3分／1分です。ダッシュボードの表示切り替えと報告ボタン、サーバーの受付期限も設定に合わせます。

予約終了時の通知はメンバーが本人の設定で切り替えます。通知はクライアントの報告期限まで再試行し、期限切れの通知は送りません。報告期限の変更は既存予約にも適用されます。

## 消灯後に接続できない場合

予約サーバー自身の電源要求を追加し、管理画面側だけが保護されていた実装を修正しました。消灯はWindowsへの実消灯要求を維持します。保護モジュールの欠損や要求失敗では消灯を無効にするため、管理画面だけを差し替えず、インストーラまたはZIPを一式更新してください。この修正は今回のRC版に収録しています。[調査内容・実機での確認手順](screen-off-investigation.md)を参照してください。

### スタンプとインクの配布・報酬

「アイテム・特典」からおふろスタンプとスタンプのインクを配布できます。持ち物一覧・配布履歴・固定報酬・ルーレットの出現比率にも対応します。

初期状態では、おふろスタンプの出現比率は0で、固定報酬にも選択されていません。使わせたいメンバーへスタンプ本体を配布してください。インクは出現比率1・個数1で、既存4種類と同じ当選確率です。既存の設定を更新した場合も、他の種類の設定を保ってこの初期値を補います。

インクは、本人の今週の今日までの未確定または失敗の日を1日だけ成功へ変えます。スタンプ本体は消費せず、インクを1個消費します。入浴完了報告や予約・ダッシュボードの入浴状況は変更しません。

## 曜日ごとの自動希望

各メンバー本人が「設定」で曜日ごとの開始時刻・長さ・備考を保存します。初期は無効です。サーバーが日本時間0:00以降に一度だけ希望を作り、通常と同じ優先順・重複判定・通知を使います。ランダム抽選を自動で行う機能ではありません。固定順ではその日の順番に従って自動確定を進めます。

サーバーが停止していた場合は起動時に当日分だけ処理します。再起動や手動の取り消しで同じ日に繰り返し作りません。設定や実行記録はデータベースに保存され、全データリセットの対象です。画面を開いていなくても時刻に実行します。時間の刻み幅・上限を変更した場合は、本人に自動予約設定の見直しを案内してください。

## 旧RC版から再公開RC版への更新

以前のrc2〜rc4は版番号の比較では新しいため、管理画面の更新確認で再公開rcが表示されない場合があります。サーバーを終了し、新しいインストーラを手動で実行して同じ場所へ上書きしてください。ZIP版は新しいフォルダーへ展開します。データフォルダーは保持し、更新前にバックアップしてください。
