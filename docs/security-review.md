# セキュリティ確認（2026-10-31）

対象はv2.0.0開発ブランチのソースです。公開済みv2.0.0-rcの配布物へ、この修正はまだ含まれていません。実際の利用データ・パスワード・秘密鍵は読み取らず、メモリ上のテスト用データで確認しました。

## 修正した問題

### 重要：認証前の不正URLによるサーバー停止

HTTPリクエストのURLを認証より前に解析しており、解析エラーが捕捉されていませんでした。ローカルの独立したテスト用プロセスに不正なURLを1件送ると、`ERR_INVALID_URL`でプロセスが終了することを確認しました。HTTPリスナーへ到達できる相手はログイン不要で予約・通知のサービスを停止させられます。Tailscaleなどの中継がこの形式を通すかは実機未検証です。

`src/request-url.js`で通常のパス形式だけを受け付け、不正なURLには400を返すようにしました。APIを直接呼ぶ場合も解析を例外処理の内側へ移しました。HTTPから呼んだAPIの予期しない同期例外・Promiseの失敗にも、プロセスを終了させず、内部のエラー内容を含まない500を返します。

認証ゲートの有無それぞれについて、不正URLを繰り返した後も通常のアクセスに応答する回帰テストを追加しました。

## 確認した対策

- 共通認証前のメンバー名・予約情報の非公開、個別ログイン後の操作制限、他人のプレゼント受取・パスキー削除の拒否を既存テストで確認しました。
- パスワードのscryptハッシュ、セッショントークンのランダム生成とハッシュ保存、HttpOnly・SameSite Cookie、固定HTTPS先でのSecure属性、パスワード変更時のセッション・パスキー失効を確認しました。
- POSTのOrigin・JSON制限、パスキーの署名・RP・Origin・利用者確認、チャレンジの期限・一回限りの消費、メンバー名・備考のHTMLエスケープを確認しました。
- 公開HTTP APIに管理者のリセット・配布・パスワード変更を追加していないこと、ローカル管理通信にランダムトークン認証があることを確認しました。
- 通知先はApple・Google・MozillaのHTTPSホストに制限され、ローカルIPや任意の送信先への変更は拒否されます。
- 更新の配布先・HTTPS・サイズ・SHA-256・バージョン、ZIPのパスと内部ハッシュ、データファイル混入の検証を確認しました。
- `npm audit`は既知の脆弱性0件でした。Git追跡中のテキストファイルで、秘密鍵・GitHubトークン・AWSアクセスIDの代表的な形式との一致はありませんでした。全形式の秘密情報やGit履歴全体を保証する検査ではありません。

今回のNodeテストは追加4件を含む141件すべて成功しました。外部からの侵入試験、実際のWindowsのアクセス制御、実機の公開中継を通した攻撃、未知の依存ライブラリ脆弱性まで確認したものではありません。
