# v2.1.0向けの実装・不具合調査（2026-11-05）

作業開始は04:25:44 UTC（日本時間13:25:44）。依頼された90分の枠で調査中です。公開済みv2.0.0-beta2のタグ・Release・配布物は変更しません。実際の家族のDB・バックアップを使用せず、一時DBと合成メンバーで確認しています。

## 依頼された動作

- 本人の画面からの完了報告はサーバー管理画面の共通設定とし、初期ではオフ。ダッシュボードからの報告と過去の完了記録を維持します。
- 有効な報告方法の期限を過ぎ、予約が属する日の受付終了までにホームを開いた場合、未報告の再予約を確認します。同じ予約には一度だけ自動表示し、後から手動でも開けます。
- 再予約の保存前・保存失敗時には元の枠を保持し、保存成功後だけ置き換えます。送信結果が届かなかった場合の再送でアイテムを二重消費しません。
- 初期オンの通知は、事前希望の確定失敗・入浴前・完了報告のお願い・つつくの4種類。既存の個別設定は維持します。

## 再現して修正した問題

| 問題 | 修正・確認 |
| --- | --- |
| 日付を切り替えただけで「予約する番」の通知が出る | 更新前の日付と比較。ブラウザーで前日への切り替えを確認 |
| 長さの選択肢が多い設定で、使用アイテムを変えると選択中の長さが戻る。時間変更不可も外れる | プルダウンとチェック状態を引き継ぎ、180分・備考・ガードを保存まで確認 |
| 公開経路などからHTMLのエラー応答が来るとJSON解析エラーになる | 接続を確認して再試行できる日本語の案内に変更。保存済みなのに502が返るケースも確認 |
| 旧様子見設定の保存失敗時に曜日設定だけ書き換わる | 同じセーブポイントで更新し、DBエラー時に両方取り消す |
| 完了報告の期限を変更・再延長すると通知が重複する。送信中のキュー再作成でも起きる | 予約revisionと通知先のハッシュで成功送信を記録。再登録・再起動後も同じ通知を繰り返さない |
| 入浴前通知の送信中に「何分前」を変えると同じ開始時刻への通知が重複する | 開始時刻単位で送信済みにする。実際の予約開始時刻を変更した場合は新しい通知を保持 |

## 確認方法

- `npm test`：API・ドメイン205件（途中経過、全件成功）。期限の直前直後・翌朝・受付終了・別人による操作・設定の保持・再送を含みます。
- `npm run test:browser`：Chromium、390×844、5ケース。再予約・入力内容の保持・日付変更・認証切れ・HTMLエラーからの再試行。実機iPhoneではありません。
- `npm run test:sequences`：再現可能なseedで日付を進め、複数メンバーの予約・希望・様子見・取り消し・完了・アイテム・設定変更を混在。各操作後に確定予約の実時刻での非重複、残高と台帳の一致、外部キー整合性、予期しない500の有無を確認します。
- Windows管理画面のチェックに、本人の完了報告の初期オフ・期限欄の有効切り替え・保存JSONを追加しました。Windows CIと配布物チェックは別途実施します。
