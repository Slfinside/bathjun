# 自動更新とお知らせ（v2.0.1）

## サーバーの自動更新

管理画面の「稼働状況」に、自動更新の設定があります。初期は有効で、毎朝 **4:00（日本時間）** にGitHubの新しい安定版を確認します。変更した場合は「自動更新の設定を保存」を押してください。

新しい版があれば、インストーラ版はインストーラ、ZIP版はZIPを取得します。配布先・バージョン・SHA-256と配布物の内容を検証し、データを残して更新・再起動します。公開モードで動いていたインストーラ版は公開モードに戻ります。ダウンロード中はサーバーを継続し、適用時だけ一時停止します。停止前に更新プログラムがスリープ防止を引き継ぎ、再起動したサーバーの稼働状態とスリープ防止の有効化を確認するまで保持します。

- 入浴中、または予約開始10分前からは適用を見送り、15分後に再確認します。設定・お知らせなどの保存中も見送ります。
- サーバーが止まっていた場合は、起動後、その日の確認時刻を過ぎていれば確認します。
- 新しい版がなければ、その日は再確認しません。接続失敗・GitHubの取得制限などは1時間後に再試行します。状況は管理画面に表示します。
- 自動更新を無効にしても「最新版を確認」から手動で更新できます。
- **リポジトリとリリースが公開されていることが必要です。** 非公開の間は自動取得できません。GitHubの個人トークンをアプリに埋め込むことはしません。インストーラを手動で取得して更新する方法は引き続き使えます。

インストール完了後はサーバーを自動で起動します。初回は合い言葉やTailscaleの設定が必要です。通常の更新では以前のローカル／公開モードを引き継ぎます。旧版が起動モードを記録していない場合、インストーラからの起動は公開モードになります。ZIP版はローカル専用です。

## 管理者がお知らせを作る

1. 管理画面の「お知らせ」を開き、「新しいお知らせ」を押します。
2. 管理用の名前を入力します。これは保存したお知らせを選ぶための名前です。
3. 表の各行に、1ページ分の**タイトル・本文**を入力します。「ページ追加」「ページ削除」で1〜10ページにします。行の順に表示します。長い本文や改行は、行を選んで「本文を編集」から入力できます。
4. 画像を付ける行を選んで「画像を選ぶ」を押します。**1ページ1枚、PNG/JPEG、1枚2MBまで**です。画像なしのページも作れます。保存後はPC上の元画像を移動しても表示できます。
5. 「下書き」「今すぐ配信」「日時を指定して配信」を選び、「お知らせを保存・配信」を押します。予約日時は**サーバーPCの日時設定**に従います。配信予定時刻にPCが停止していた場合、次の起動・アクセス時に配信します。

保存済みのお知らせは上の一覧から選べます。下書き・予約済みは編集できます。配信済みは編集せず、新しいお知らせとして作成してください。「配信を終了／予約を取り消す」で未読の人への表示を止められます。最近50件を一覧に表示し、配信時刻・確認した人数・過去の配信データをサーバーに記録します。

**お知らせの配信ではプッシュ通知を送りません。** 利用者がログインしてホームを開いたときに、未読のお知らせを表示します。「次へ」で進むか、ボタン下の「スキップする」で閉じられます。読み終わり・スキップはメンバーごとに記録するので、別の端末でログインしても同じお知らせを繰り返し表示しません。画像はログイン中のメンバーだけが取得できます。

## 更新に同梱するお知らせ

v2.0.1には3ページのテスト用お知らせが入っています。架空のメンバーで作成した画面、予約用アイテム、おふろスタンプとインクの画像を使っています。

- インストーラによる**別バージョンからの更新**、または管理画面から検証済みZIPを適用した更新のあとに、一度だけ配信します。
- 新規インストールや通常の再起動では同梱のお知らせを新しく配信しません。
- 更新起動の記録と、配信したバージョンの履歴を照合します。同じ版の再インストールや、更新処理の再試行で二重配信しません。
- 各メンバーの初回アクセスで表示します。更新の直後に全員へ通知することはありません。
- 全データのリセットでは、お知らせと既読記録も削除します。同じ版を配信し直さないためのインストール履歴は残します。

開発時は `release-announcements/<version>.json` と同じフォルダー内の画像を更新してください。ビルドでは現在のバージョンのお知らせ・画像の同梱を検証します。ローカルの予約データや実際の家族の画面を素材に使わないでください。

## スタンプのインクが戻る場合

**今日の未確定「−」にインクでスタンプを押したあと、同じ日分のおふろの完了を受付時間内に報告した場合**、インク1個をプレゼントボックスへ返します。持ち物へ直接加算せず、通常のプレゼントと同じように受け取れます。

過去の日への使用、既に失敗「×」になっていた日への使用、受付時間外・予約が一致しない報告は対象外です。報告を何度送っても返却は1回だけです。予約終了前に上がって報告した場合も、通常の受付条件を満たしていれば対象です。この返却記録の対象はv2.0.1以降に使ったインクです。
