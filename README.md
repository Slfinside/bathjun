## 管理者権限なしで、このPC内だけテストする

**`Bathjun-Portable-x64.zip`** をすべて展開し、**「はじめる.cmd」** を開いてください。Node.jsと必要なライブラリ・操作画面を同梱しているので、管理者権限・Node.jsの個別インストール・Tailscale・インストーラーは不要です。Windows 10/11の64bit版向けです。

初回はテスト用の合い言葉を設定します。ブラウザーの予約画面と、メンバー・時間・抽選／固定順を設定するサーバー操作画面が開きます。接続先は **127.0.0.1のみ**。継承したHOST設定があっても、Windowsのローカル起動ではループバックへ限定します。

テストデータは **`%LOCALAPPDATA%\BathjunTestData`** に保存し、通常版の `BathjunData` と分離します。学校PCでは本番の合い言葉・データを使わず、テスト用を設定してください。ローカル版は外部公開や別端末接続を行わず、iPhoneへのプッシュ通知は試せません。パスキーはlocalhost上のWindows Hello等を使えますが、可否は学校PCの設定によります。抽選・予約の時刻条件は通常どおりです。

ZIP版はサービス・自動起動・インストールのレジストリ登録を行いません。アプリ・スクリプトの実行自体が学校のポリシーで禁止されている場合は起動できないので、管理者へ確認してください。実行制限・ネットワーク制限・電源ポリシーを回避する機能はありません。Windows実機での起動は未検証です。詳しくは同梱の「はじめに.txt」を参照してください。

## Windowsインストーラー

**`Bathjun-Setup-x64.exe`** の初期選択は本体のみです。ユーザー用フォルダへ管理者権限なしで導入し、デスクトップの「ふろじゅん」からこのPC内だけで起動します。Sモード非対応、インストーラー自体は未署名です。

外部公開をするPCでは、セットアップの任意項目 **「無料固定URL用のTailscale」** を選ぶか、既存のTailscaleを使います。初回導入にはインターネット接続とWindows管理者の許可が必要です。公式パッケージを取得し、有効な「Tailscale Inc.」のAuthenticode署名を検証します。管理者権限が使えないPCでは、この項目を選ばずローカルテスト版を使ってください。

外部公開を使うときは、ローカルサーバーをいったん停止し、スタートメニューの **「固定URLで外部公開」** を開きます。Tailscaleの無料アカウントにサインインし、HTTPS/Funnelを許可すると、確認済みの長い固定リンクを表示します。iPhoneへはそのリンクを共有します。各自が初回に家族の合い言葉・名前・個別パスワードを設定し、パスキーを登録します。

本体は `%LOCALAPPDATA%\Bathjun`、通常版のデータは `%LOCALAPPDATA%\BathjunData`。更新・アンインストールでもデータを残します。Tailscaleは共有の接続サービスなので、アプリ削除時に自動削除しません。任意のサインイン時自動起動も、このPC内モードで起動します。

サーバーはNode.js・SQLiteと小さいネイティブ操作画面で動かし、ブラウザーやElectronを常駐必須にしません。通知キューが空なら周期タイマーを置きません。Windows版はパスワード処理用ワーカー2つ・Node旧世代ヒープ上限96MiB（全体RAM上限ではありません）。以前のLinux測定でNode単体の待機時RSSは39.3MiBでした。Windowsと操作画面・Tailscaleを含む実機値ではありません。

稼働中の消灯はAC電源で操作画面のボタンを使ってください。電源設定は恒久変更しません。**Windows実機の導入・操作画面・消灯、Tailscaleのサインインと公開、iPhoneの実通知・Face IDは未検証**です。このクラウドではTailscale公式サイトが403で拒否されており、実際の公開URLは利用するPCで初回設定後に発行します。

## Windowsのサーバー操作画面と消灯

サーバー起動時には、小さい **Windowsネイティブの操作画面** が開きます。ターミナルは起動ログと初回の合い言葉入力用に残します。ブラウザー・WebView・PowerShellを操作画面として常駐させる構成ではありません。Windowsにある.NET Frameworkを使う小さな専用EXEを同梱します。

- **稼働状況**：接続状態、家族用リンク、リンクをコピー、予約画面を開く、画面だけ消す、サーバー停止。
- **設定**：メンバー名・人数・利用状態、入浴時間帯、抽選時間、予約の最小・最大・刻み幅、抽選／固定順。

**AC電源につなぎ、「画面だけ消す（サーバーは継続）」を押します。** 1秒後にディスプレイだけを消し、タッチやマウス・キーボードで戻れます。稼働中はWindowsの `PowerRequestSystemRequired` と `PowerRequestExecutionRequired` を保持し、自動スリープ・実行停止を抑止します。サーバー終了・操作画面の切断時には要求を解放します。電源プランやレジストリを恒久変更しません。

操作画面の×は通知領域へしまう動作で、サーバーと電源要求は継続します。通知領域またはデスクトップのショートカットから戻れます。停止は画面の **「サーバーを停止して終了」** かターミナルのCtrl+C。操作画面が異常終了した場合はサーバーも停止します。

Windowsの仕様上、電源ボタン・カバー閉じ・スタートメニューからの手動スリープ、電源断やOS終了は抑止できません。Modern Standby対応PCはバッテリー上での要求にも制限があるので、消灯ボタンはAC電源時だけ有効にしています。復帰・電源状態変化時には要求を更新します。**実機での消灯・電源制御は未検証**なので、初回は消灯後にもスマートフォンから予約画面へ接続できるか確認してください。

## サーバー設定：メンバー・時間帯・固定順

設定はPCの操作画面から行います。家族用の公開Web画面に設定変更・消灯・停止の管理APIは公開しません。操作画面とNodeの間だけで、ランダムな認証トークンを持つローカルの名前付きパイプを使います。

メンバーは1〜50件で設定できます。「追加する名前」に入力し、「メンバーを追加」で表に追加してから「設定を保存」を押します。複数人を続けて追加できます。名前欄に入力したまま保存した場合も取り込みます。初期状態はメンバー未登録です。サーバー操作の「設定」で名前を追加してください。名前と利用状態は保存後すぐ反映します。既存メンバーのID・予約・パスキーを壊さないよう削除は行わず、使わない人は「利用する」のチェックを外します。利用停止時はログイン状態を失効させ、パスキーでも入れなくします。履歴と既存予約は残ります。再開すると既存の個別パスワード・パスキーを使えます。

入浴時間帯は最長24時間、予約の刻み幅は5・10・15・30分から選べます。最小・最大時間は刻み幅の倍数で、入浴時間帯に収まる値を指定します。抽選時間の制限は初期状態では無効です。有効にした場合は、同日の入浴開始までに抽選を終える時間帯を設定してください。制限なしでも翌日夜の先行抽選や、おふろ終了後の抽選はできません。

**時間帯と予約順モードの変更は翌日分から反映**します。今日の予約と元の順番を変更しません。将来の設定を同日に保存し直すと、翌日向けの値を更新します。追加したメンバーは次の順番決定から参加します。

- **毎日抽選**：時間制限が有効なら設定した抽選時間中に誰かが押して、全員共通のランダム順を1日1回決めます。
- **固定順**：メンバー表の並びを「選択行を上へ／下へ」で変えて保存します。日々の抽選は不要で、その日を開いたときに固定順を確定します。利用停止の人は予約対象外です。「入らない/様子見」の人はその日の末尾へ回せます。

元の抽選・固定順と、その日の様子見による末尾移動は分けて保存します。通常順へ戻しても再抽選は行いません。変更した名前・人数・時間帯は、クライアント画面の選択肢や案内にも反映します。

## iPhoneのホーム画面へ追加

Safariで固定HTTPSの家族用リンクを開き、**共有 → ホーム画面に追加 → 追加** を選びます。「Webアプリとして開く」が表示されたらオンにしてください。ホーム画面には「ふろじゅん」のアイコンが置かれ、そこからはSafariのアドレスバーなしの画面で開きます。Safariで表示中はフッターの **「ホーム画面への追加方法」** から手順を確認できます。追加済みのアプリ内ではこの案内を隠します。

Web App Manifestのstandalone表示、アイコン、ルートscope、Apple向けメタタグ、ノッチ・ホームインジケーターの余白を設定しています。起動URLで家族用リンクの通過状態を更新し、パスキーと通知を同じ固定オリジンで使います。iOS 16.4以降の通知は、追加したアプリ内から許可してください。予約はサーバーへの接続が必要で、オフライン予約にはしていません。実機Safariでのホーム画面追加は未検証です。

## パスキー：二回目からは両パスワードを省略

初回は家族の合い言葉で家族専用画面を開き、名前を自己申告して個別パスワードを設定します。ログイン後にパスキーを登録すると、次回以降は **「パスキーでログイン」→ Face ID / Windows Hello / PINなど** で本人を確認し、家族共通・個別の両パスワード入力を省略します。ログイン状態が残っているときは、そのまま使えます。

パスキーは**固定のHTTPS家族用リンクで登録**してください。サーバーが保持するのは公開鍵とメンバーの対応だけです。パスキーの秘密鍵や顔・指紋はサーバーへ送りません。端末の同期設定によっては同じパスキーを複数端末で使えますが、別端末では初回の手順で入り直して、その端末用のパスキーを登録することもできます。

家族認証前でもパスキーのログインができ、署名済みの資格情報から利用者を判別します。登録には家族認証と個別ログインが必要です。チャレンジは5分・1回限りで、RP/Origin/署名/利用者確認を検証します。実際の署名を作る自動テストと、ブラウザーの仮想認証器で登録・ログイン・再使用と偽署名の拒否を確認しています。

「登録済みを確認・削除」で本人のパスキーだけ削除できます。端末側のパスキー管理に残る項目は、必要に応じて端末側からも削除してください。パスキーを失ったときは従来のパスワード認証で復旧できます。共通の合い言葉の変更は、すべてのセッションと登録済みパスキーを解除します。個別パスワードの管理者リセットも、その人のパスキーを解除します。

## Macから一時URLで試す（従来の試用モード）

1. [Node.js](https://nodejs.org/) **24以降** をインストールします。
2. Macのターミナルで `brew install cloudflared` を実行します。Homebrewがない場合は、[Cloudflare公式のインストール案内](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/)を利用してください。
3. フォルダ内の **`外から使う.command`** をダブルクリックします。初回はnpmの依存関係を自動インストールします。
4. 初回だけ、ターミナルで **家族の合い言葉（8〜128文字）** を2回設定します。入力文字は表示されず、平文では保存されません。
5. 接続確認後に表示される **長い家族用HTTPSリンク** と合い言葉を、家族だけに共有します。Macではブラウザーも開きます。

アクセスの順序は **長い家族用リンク → 家族の合い言葉 → 自分の名前・個別パスワード**。合い言葉で認証する前は、家族の名前や予約内容を取得できません。個別パスワードは、各自が最初に自分の名前を選んだときに設定します。

外部公開中は、ログイン後の画面にある「家族用リンクをコピー」でも共有できます。アドレス欄は認証後に短いURLになるので、共有用ボタンまたはターミナルに表示された長いリンクを使ってください。

**Macの電源とターミナルはつけたままにしてください。** スリープ中や終了後はアクセスも通知送信もできません。終了はControl+C。ルーターのポート開放やCloudflareアカウントは不要です。サーバーはMacのループバックだけで待ち受け、トンネルを通じてHTTPSで公開します。

### 試用URLの制約

Cloudflare Quick Tunnelは試用向けで、稼働保証がありません。**公開起動のたびにドメインが変わります。** 再起動したら新しいリンクを共有してください。iPhoneのホーム画面への追加・通知許可も、新しいドメインで設定し直す必要があります。同じドメインで継続運用するには、Cloudflareアカウントと管理できるドメインを使った固定トンネル等への変更が必要です。

URLには暗号学的乱数256ビット（64桁の16進数）を含み、長いリンクを通っていない端末には画面・API・静的ファイルを返しません。加えて家族共通・個別のパスワード認証を行います。長いURLを知っているだけでは予約にアクセスできません。

この作業環境ではCloudflareのトンネル用DNS接続が拒否されたため、**実際の公開URLの発行・インターネット経由の到達性は未検証**です。Mac側で起動して接続を確認してください。接続できない場合、公開リンクを発行したかのような表示は行いません。

## iPhoneで予約順・予約開始10分前の通知を受け取る

**iOS 16.4以降** が必要です。

1. 長いHTTPSリンクをSafariで開き、家族の合い言葉を入力します。
2. Safariの「共有 → ホーム画面に追加」でアプリを追加します。
3. 追加したアプリを開き、自分の名前でログインします。
4. 画面の **「通知を受け取る」** を押し、iPhoneの通知を許可します。

前の人が予約し終えて自分の番になると、登録した端末へWebプッシュを送信します。抽選直後の1番の人にも通知します。通知をタップすると、その日のおふろ画面を開きます。アプリを閉じている間もプッシュを受け取れますが、送信元のサーバー用PCは稼働している必要があります。

通知先は現在ログインしている人に紐づきます。ログアウトすると、そのログイン状態に登録した通知先を解除します。別の人でログインした端末には、その人の番を通知します。画面の「通知を止める」で端末ごとに解除できます。

一時的な送信失敗はSQLiteの送信待ちキューに残して再試行します。すでに予約が済んだ人への古い通知や、編集による同じ番の重複通知は送信しません。無効になった通知先は削除します。通知プロバイダーで受理された後の配送は端末・サービスの状態に依存します。

HTTPの自宅LANアドレスではiPhoneへのバックグラウンド通知は使えません。アプリを表示中は未予約者を約5秒、予約済み・入らない/様子見の人は約15秒、全員の予定が決まったら約60秒ごとに更新します。画面を非表示にするとポーリングを止め、再表示時にすぐ更新します。自分の番へ変わると画面内でもお知らせします。

実機iPhoneへの配信は未検証です。自動テストでは、誰に送信するか、重複・古い通知の抑制、失敗時の再試行、ログアウト時の解除を検証しています。プッシュの暗号化・署名には `web-push` を使い、VAPID鍵をSQLiteに保存します。通知サービスのアカウントや有料契約は不要です。

## 備考と「時間変更の相談不可」

予約・変更の画面で、次の項目を**任意で**指定できます。

- **備考**：300文字まで。「出張で明日は早起きなので、この時間に入りたい」など。
- **時間変更不可**：チェックしたときだけ、予約一覧に表示します。

どちらも家族全員の予約一覧に表示され、後から本人が編集できます。予約した本人は開始前なら時刻も変更できます。この表示は家族への意思表示で、予約を自動で固定する機能や交渉用チャットではありません。

## Mac内・同じWi-Fiだけで試す

**`おふろを起動.command`** をダブルクリックします。初回は依存関係のインストールと家族の合い言葉の設定を行い、ローカル用のサーバーを起動します。ターミナルに出るアドレスを同じWi-FiのiPhoneから開くこともできます。外部公開とは同時に起動せず、いったんControl+Cで終了してから切り替えてください。

ターミナルからの起動は次のとおりです。

```sh
npm ci
npm run family:password  # 初回、または家族の合い言葉を変更するとき
npm start               # 自宅LAN向け
# または
npm run public          # 外出先からのHTTPSアクセス用。cloudflaredが必要
```

Node.jsやcloudflaredを見つけられない場合はターミナルから実行してください。実行権限がない場合は `chmod +x *.command` を実行します。

## わが家のルール

- 初期メンバーは未登録（サーバー操作の「設定」で追加）。メンバーと以下のルールはサーバー設定で変更できます。
- 時刻は常に **日本時間**。ある日15:00〜翌日7:00が、その日のおふろ枠です。
- 抽選時間の制限は初期状態では無効です。有効にした場合の初期時間帯は **当日6:00〜14:59**。誰かが抽選すると、1日1回のランダムな **予約の優先順位** を全員で共有し、引き直しはできません。
- 6:00〜6:59は昨日のおふろ枠も有効です。今日の抽選は「今日の夜～」を選んでください。
- 抽選順に1人ずつ、好きな空き時間を予約します。実際に入浴する順番は選んだ時刻で決まります。
- 1人1枠、**15〜90分・15分刻み**。脱衣所に入ってから着替えて出るまでを含み、翌7:00までに終了します。
- 重複はサーバー側で拒否します。開始前なら本人が変更・取り消しできます。予約だけを取り消した人は未予約者として順番に戻ります。「入らない/様子見」は末尾へ回ります。
- 時間制限が有効な場合の時間外抽選、過去の時刻への予約、開始済み予約の変更はできません。自動抽選はありません。

## 入らない/様子見と、順番前の希望

**「入らない/様子見」** は「今日は絶対に入らない」という意味ではなく、その日の予約順の末尾へ回す操作です。複数人が選ぶと選択した順に末尾へ並びます。抽選前でも選べ、末尾の順番が回ってきたら予約できます。選択時に未来の予約・希望がある場合は、確認後に取り消します。開始済みの予約は変更できません。

様子見中でも希望を共有できます。**「通常の順番に戻す」** で元の抽選・固定順に戻れます。予約時刻だけを取り消して選び直す場合は、変更画面の **「この予約を取り消す」** を使ってください。

**「事前希望 → 希望を出す」** から、順番前でも時刻・所要時間・理由（任意300文字）を共有できます。全員に **「希望・未確定」** として表示し、本人が変更・取り消しできます。重複する希望も投稿できます。本人の予約順が回ってきて、開始前の有効な希望がほかの予約・希望のどちらとも重ならなければ、理由を引き継いで自動確定します。重なりがあれば未確定のまま止まり、本人が予約時刻を選べます。重なった予約・希望の変更・取り消しで空いた場合にも再判定します。空きが続けば後続メンバーの希望も順に確定します。自動確定した希望は希望一覧から消え、予約側に「希望から自動確定」と表示します。実際の予約時には重複を拒否します。

## パスワードの変更・復旧

Windowsでは、サーバー操作画面の **「パスワード・リセット」** タブから家族共通・各メンバーの設定状態を確認できます。現在のパスワード自体は表示できませんが、入力した内容が現在のものかを照合できます。忘れた場合は、対象を選び、新しいパスワードを2回入力して変更します。現在のパスワードは不要です。「入力した内容を表示」は入力欄だけを表示します。パスワードの原文は保存しません。個別の変更はその人、共通の変更は全員のセッション・パスキー・通知登録を解除します。予約・メンバー・アイコンは残ります。

以下のターミナル操作も引き続き使えます。

家族の合い言葉はMacのターミナルで設定・変更します。チャットやソースに書き込まないでください。

```sh
npm run family:password
```

変更すると全端末の家族認証と個別ログイン・通知登録・パスキー登録が解除されます。予約・抽選結果・個別パスワードは残ります。各端末は新しい合い言葉で入り直し、通知も有効にしてください。

個別パスワードは4〜128文字です。メール認証を使わないため、自分の名前だけ初回設定してください。忘れた場合はMacの管理者が次を実行できます。指定した人だけ初回設定に戻り、ログインと通知登録・パスキー登録が解除されます。予約は消えません。

```sh
node src/reset-password.js 登録した名前
```

共通・個別ともパスワードはソルト付きscryptハッシュで保存します。個別は5回、家族共通は10回の誤入力で15分ロックします。個別ログインは30日、家族認証は180日で失効しますが、パスキーログインでも再発行します。リンクの通過状態は最長400日で、ホーム画面からの起動でも更新します。

## データと更新

保存先は **`data/bathjun.sqlite`**。バックアップはアプリを停止してから **`data` フォルダごと** コピーしてください。更新時は既存の `data` を残してアプリのファイルを置き換え、`npm ci` を実行します。起動時の追加マイグレーションで既存の予約を維持します。配布ZIPとGitには `data` を含めません。

データベースにはハッシュ化したパスワード、通知用の秘密鍵、家族用リンクの乱数も含まれます。データフォルダやバックアップは家族以外に共有しないでください。

## 開発と検証

Node.js 24以降。macOS・Linux対応です。

```sh
npm ci
npm run dev
npm test
```

テストは一時DBを使用し、実際の予約には触れません。日本時間の日付境界、抽選、認証、公開リンクの保護、予約順と重複、備考と任意表示、通知送信の対象と再試行、データ保持などを検証します。プッシュサービスへの通信はテスト用送信処理で置き換えます。

`PORT=3001 npm start` でポートを変更できます。LAN用サーバーの既定は `0.0.0.0:3000`、公開用は `127.0.0.1:3000` です。`BATHJUN_DB` でDBファイルを、`CLOUDFLARED` でcloudflared実行ファイルを指定できます。

## Windows版を再ビルドする

NSIS 3.11以降・Python 3・Node.js・C#コンパイラー（Mono mcsなど）があるビルド用マシンで `python packaging/build-windows.py --makensis makensis --csc mcs` を実行します。アプリ本体・固定バージョンの公式Node.jsとライセンス・JS依存だけを集め、チェックサムを検証してから `dist/Bathjun-Setup-x64.exe` を作ります。`data`・秘密鍵・既存パスワード・予約・開発テスト用データは含めません。配布するNode.jsのバージョンとSHA-256は `packaging/windows/runtime-lock.json` で管理しています。TailscaleはPC側で署名を検証して導入するため、初回のオンライン接続が必要です。

## 予定表と設定案内

「昨日の夜～／今日の夜～／明日の夜～」で切り替えます。明日の夜は設定の確認用で、先行して抽選・予約はできません。未来の固定順を表示だけで確定することもありません。

予定表は15分ごとの時刻目盛りを表示します。2時間以上の連続した空き時間だけ波線で省略し、前後の時刻を表示します。予約や希望がある区間は省略しません。未確定の希望は薄い色と点線で表示し、重なる予定もそれぞれの時刻とともに並べます。

登録済みのパスキーと、この端末で有効な通知は、通常の設定案内を非表示にします。変更・削除・追加登録は折りたたみの「ログイン・通知の設定」から行えます。通知の許可が外れた場合は再び案内します。

設定保存の通信は画面操作スレッドから分離しています。15秒以内に応答を確認できない場合は未確認と表示します。「設定を再読込」で保存結果を確認してください。Windows実機でのUI動作は未検証です。

ネイティブ通信の回帰テストは `packaging/windows/tests/PanelOutboxTest.cs` を、ビルド済み `Bathjun-Server.exe` と `System.Web.Extensions.dll` を参照してコンパイル・実行します。通信先の書き込みを意図的に停止しても送信操作が戻ること、キュー上限・順序・切断時のエラーを検証します。

## アイコン

未設定のアイコンは灰色の「？」です。初回の個別パスワード設定で絵文字と色を選びます。16色のプリセットと、スポイトマークから開く自由な色指定・カラーコード入力を用意しています。選択内容はサーバーで共有・保存し、再ログイン後も使います。既存ユーザーや後からの変更は、折りたたみの「ログイン・通知の設定 → アイコンを変更」から行えます。

## 全データのリセット

サーバーの **「パスワード・リセット → 全データをリセット」** から行います。削除内容を確認し、「リセット」と入力すると実行できます。メンバー・アイコン・予約・希望・抽選・時間設定・パスワード・サーバー側のパスキー・ログイン・通知登録を削除します。メンバー未登録、抽選時間制限なしの初期状態に戻し、家族用リンクと通知用の鍵も更新します。過去のリンクは使えなくなります。管理画面で家族の合い言葉を変更し、設定タブでメンバーを追加して使い直せます。アプリ本体やTailscaleアカウントは削除しません。端末のパスキー保管庫にある項目は、必要に応じて端末側で削除してください。

パスワード管理とリセットは、認証されたローカル管理用通信でだけ受け付けます。家族用の公開APIには管理操作を追加していません。

## 予約開始10分前の通知

通知を有効にした本人の端末へ、予約開始10分前にもWeb Pushを送ります。自動確定した事前希望も対象で、未確定の希望は対象外です。予約時刻の変更では新しい時刻へ合わせ、キャンセル・様子見・通知解除・ログアウトでは取り消します。同じ予約への同じ端末の通知は1回です。備考だけの変更や同じ通知登録では送信済みの通知を再送しません。

予約確定や通知登録の時点で10分を切っていて、まだ開始前なら即時通知します。サーバー再起動後も予約と予定を復元し、開始済みの予約への遅延通知は送りません。一時的な送信失敗は開始時刻まで再試行し、Push配信の有効期限も開始時刻までに制限します。サーバーPCの稼働・端末の通知許可が必要で、OSや通信状況による遅延はあり得ます。通知待ちには既存の単発タイマーを使い、アイドル時の定期ポーリングは追加しません。
